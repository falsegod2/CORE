Generic Task-Evidence ProtoNet v2 modification summary
=======================================================

1. Replaced the default sheep/tree-dependent time-to-success prototype labels
   with generic task-evidence labels:
       class 0 = Low task evidence
       class 1 = Medium task evidence
       class 2 = High task evidence
       class 3 = real environment Success
       -1      = Unknown / ambiguous

2. Added raw MineCLIP task score to replay:
   - envs/tasks/base/clip_wrapper.py now exports `task_score` in [0,1].
   - envs/tasks/base/ls_imagine_wrapper.py carries it into observation/replay.
   - It is auxiliary-only; the encoder remains RGB-only.

3. Generic teacher combines:
       0.65 semantic MineCLIP task score
       0.30 task-conditioned affordance heatmap top-k response
       0.05 intrinsic progress event
   Components are robustly q05-q95 normalized per replay batch, so the same
   parameters can be used across tasks with different raw signal scales.

4. Stage thresholds are adaptive batch quantiles (q30/q70), with a dead-zone
   around thresholds labelled Unknown to reduce noisy pseudo labels.

5. Real environment reward always overrides pseudo labels as Success.

6. Posterior S remains detached prototype support; S5A predicted future S is
   the differentiable query. Same fixed 2560->512 S5A projector is reused.

7. Prototype utility is NOT added to actor imagined reward.

8. Old temporal_success mode remains available only for ablation via:
       prototype_utility.label_mode: temporal_success

9. New tests verify:
   - task-generic labels exist without a success trajectory;
   - flat teacher signals stay Unknown rather than fabricating stages;
   - real reward is the hard Success anchor;
   - enabling Prototype Utility does not alter S5A RNG consumption;
   - prototype loss gradients reach existing S dynamics;
   - RGB-only encoder remains unchanged.
